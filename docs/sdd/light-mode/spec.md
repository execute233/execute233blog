# Spec：粉白亮色模式与系统主题跟随

状态：已批准（2026-10-09），已实现。主题入口为右上角独立按钮；验证记录见同目录的 `todo.md`。

## Objective（目标）

为博客访客提供完整的亮色模式，与当前玫瑰墨色暗色模式配套。亮色采用粉白背景、深梅色文字、玫红强调及灰紫辅助色，保留弱化星空；没有主题偏好记录时默认跟随系统。

这是一个全站主题能力，配色、主题选择、背景设置兼容共同构成其验收范围，不单独拆分能力模块。

用户已确定：

- 参考 [Bad0RANG3 关于页](https://bad0rang3.xyz/about/) 的亮色配色。
- 使用「粉白底＋弱化星空」。
- 默认「跟随系统」。
- 参照参考站，在右上角新增独立主题切换按钮，桌面和手机均可直接操作。

已批准的约定：

- 保留当前暗色外观、布局、导航和装饰交互。
- 「亮色／暗色／跟随系统」通过右上角独立主题按钮选择，不放在「背景 · 样式」子面板中；该面板继续负责色相和背景编辑。
- 保留已有合法主题记录；没有记录或记录无效时采用跟随系统。
- 自定义背景按亮暗模式分别保存；主题色相继续共用现有设置。
- 代码块继续采用当前 `github-dark` 配色，作为亮色页面中的深色阅读区域。

## Current State（当前基础）

- `src/constants/constants.ts` 定义 `light`、`dark`、`auto`，但默认值是 `dark`。
- `src/utils/setting-utils.ts` 使用 `theme` 存储键及 `<html>` 的 `.dark` 类控制主题。
- `LightDarkSwitch.svelte` 保留三种模式逻辑，但当前导航未挂载该组件，不能依赖它提供运行中的系统主题监听。
- `theme-tokens.css` 为 `.rose-theme` 和 `.rose-theme.dark` 应用相同暗色变量与 `color-scheme: dark`。
- `Layout.astro` 在首屏读取主题和外观设置，并在运行时再次应用主题；两处行为需要一致。
- `appearance.ts` 对所有模式写入同一个 `--blog-background`，其默认值为暗色，因此仅修改亮色 CSS 不能完成支持。
- 旧版本启动时会自动保存主题。已有 `theme=dark` 无法证明用户曾手动选择；本次保留该合法记录，避免覆盖已有偏好。访客可通过入口改为跟随系统。

主题基础整理已提交为 `4b360c9`，实现以此为基础；后续如出现工作区改动，按仓库规则保留。

## Visual Requirements（视觉要求）

参考值来自参考页公开 CSS 的 `paper` 主题；已提取源码，尚未完成浏览器视觉核验。借鉴颜色关系，不复制页面结构。

| 角色 | 亮色基准 | 本站用途 |
| --- | --- | --- |
| 页面背景 | `oklch(97.5% 0.012 355)` | 粉白页面底色 |
| 卡片、浮层 | 白色，参考透明度 72%～92% | 内容卡片、设置、搜索；阅读区优先较高不透明度 |
| 主文字 | `oklch(24% 0.045 345)` | 标题与正文的深梅色 |
| 次要文字 | `#755c68` | 摘要、日期、辅助说明的灰紫色 |
| 强调色 | `#d94f81` | 链接、选中项、焦点和按钮 |
| 紫色点缀 | `#8764c5` | 少量背景装饰 |
| 分隔线 | `rgb(76 47 61 / 14%)` | 低对比边框 |
| 阴影 | `rgb(105 47 70 / 15%)` | 柔和梅色阴影 |

上述值为视觉基准，最终映射到现有 CSS 变量；允许为对比度和现有色相设置做调整。默认色相继续以 `siteConfig.themeColor.hue` 为准，不另设相互冲突的默认值。

- 覆盖首页、博客列表、学习列表、关于、工具、归档、文章及分页页面，包含导航、页脚、目录、搜索、设置、标签、按钮、提示块、表格和行内代码。
- 亮色页面显示浅底深字；控件原生外观的 `color-scheme` 与实际主题一致。
- 星空在亮色下仍可辨认，但视觉强度低于暗色，正文区域进一步减弱；必要时适配星点材质，使白色粒子不会在浅底上完全消失。
- 普通正文和辅助文字在实际合成背景上对比度至少 4.5:1，大号文字至少 3:1；链接、选中状态、键盘焦点清晰可辨。
- 现有樱花与光标保留，检查其在浅底上的可见性；无需增加新的背景装饰或动画。
- 代码块可保留深色底和现有语法高亮；周围标题、复制按钮及语言标识须清晰可辨。

## Theme Behavior（主题行为）

| 保存的选择 | 系统外观 | 实际主题 |
| --- | --- | --- |
| 无记录、无效值或 `auto` | 亮色 | 亮色 |
| 无记录、无效值或 `auto` | 暗色 | 暗色 |
| `light` | 任意 | 亮色 |
| `dark` | 任意 | 暗色 |

- 首次绘制前确定主题，避免先出现明显的错误主题再切换；首屏逻辑与运行时逻辑使用相同规则。
- 手动选择立即生效并保存；刷新、直接访问文章和 Swup 跳转后继续生效。
- 跟随系统时，系统外观变化立即更新页面；手动亮色或暗色时不受系统变化影响。
- 控件显示保存的选择；`auto` 实际渲染为暗色时仍显示「跟随系统」。
- 系统主题监听只初始化一次，或在销毁时清理；反复导航不得重复绑定。
- 存储读取、解析或写入失败时页面仍能加载，当前会话的切换仍可用；读取失败回退到跟随系统。
- 新增文案按现有国际化规范维护，在全部语言文件补齐对应键。

## Appearance Compatibility（外观设置兼容）

- 未自定义背景时，亮色使用粉白默认值，暗色使用当前默认值。
- 旧外观存储的博客背景仅作为暗色背景迁移；旧默认值按现有迁移规则处理，其他合法自定义值保留。
- 在亮色下修改背景只影响亮色；在暗色下修改背景只影响暗色。两个值分别保存、刷新后恢复，切换时不互相覆盖。
- 跟随系统时背景编辑作用于当前实际主题。
- 「恢复默认样式」恢复当前实际主题的背景与共用色相，不改变保存的主题模式，也不清除另一模式的自定义背景。
- 切换主题不重置星空参数、暂停状态、光标设置或音乐状态。
- 「只看星空」继续作为临时预览增强星空显示，沿用当前实际主题；退出后恢复该主题的正常背景强度，不写入新的主题偏好。
- 继续遵循 `prefers-reduced-motion`，不增加并行 Canvas 动画循环。

## Code Style（代码风格）

沿用项目的制表符、双引号、分号和路径别名；复用现有主题类型、工具与 CSS 变量，不建立第二套主题状态。主题函数风格示例来自现有实现：

```typescript
export function setTheme(theme: LIGHT_DARK_MODE): void {
	localStorage.setItem("theme", theme);
	applyThemeToDocument(theme);
}
```

示例展示命名和格式；正式实现还需满足存储失败处理要求。内部 URL 使用 `url()`。CSS 变量使用现有 `--primary`、`--page-bg`、`--card-bg`、`--ink`、`--muted` 等，不在各页面重复硬编码配色。

## Testing Strategy（验证策略）

当前项目没有声明自动化测试框架或 Playwright 依赖，不假定存在 `pnpm test` 或可直接执行 `pnpm exec playwright`。优先使用环境已有浏览器或 Playwright 能力；不为纯配色添加镜像实现的测试或新的测试依赖。

- 静态检查：针对变更文件格式化及只读检查，运行 `pnpm check`；涉及 TypeScript 声明时执行 `pnpm type-check`。
- 构建检查：运行 `pnpm build`，使用构建预览验证首屏与真实 Pagefind 搜索。
- 主题行为：无记录、`auto`、`light`、`dark`、无效记录、存储不可用；系统亮暗切换，刷新及直接打开。
- 兼容验证：旧默认背景、旧自定义背景、两种模式分别自定义、当前模式恢复默认、共用色相。
- 浏览器矩阵：桌面 `1440×900` 与手机 `390×844`，补查 `767px`、`768px` 和 `800px`、`801px` 的设置及导航断点。
- 页面检查：首页、两个栏目列表、关于、工具、归档、代表性文章；文章包含目录、代码块、表格、公式和提示块。搜索在构建预览中验证，开发模式的模拟结果不算真实搜索验证。
- 导航检查：直接访问、Swup 站内跳转、前进和后退；确认主题不回退，控件状态一致，`#toc` 始终存在。
- 交互检查：键盘操作主题选择、焦点反馈、设置菜单、暂停动画、只看星空和减少动态效果。
- 证据：截图及可用 trace 保存到 `tmp/light-mode/playwright/`，记录控制台错误和失败请求；关闭本次启动的服务与浏览器，不结束已有无关进程。

浏览器连接工具不可用；实际验证使用环境已有的 Playwright 与无头 Edge，结果和测试边界见 `todo.md`。不设覆盖率数字，以本规格行为矩阵和视觉检查为验收依据。

## Boundaries（边界）

- **Always：** 保留已有未提交改动；按仓库约定先查 CodeGraph；使用 pnpm 与 PowerShell 7；先检查变更格式，再进行运行验证；主题配置与控件状态保持一致；报告真实验证范围。
- **Ask first：** 增加依赖或测试框架、改变 CI 或部署配置、覆盖合法旧主题记录、删除用户设置、扩大到页面结构重设计。需求变化先更新规格并审核。
- **Never：** 直接编辑 `dist/` 或依赖目录；提交调试缓存或秘密；全量格式化无关文件；删除整个 `tmp/`；移除 Swup 必需的 `#toc`；未经请求提交、发布或部署。

## Success Criteria（验收标准）

1. 新访客在系统亮色时看到粉白页面、深梅色文字和弱化且可辨认的星空；系统暗色时看到现有暗色外观。
2. 桌面及手机右上角均显示独立主题切换按钮，可选择三种模式，状态显示正确，操作可通过键盘完成。
3. 手动模式刷新、导航及前进后退后保留；系统外观变化仅影响跟随系统模式。
4. 首屏和运行时的主题判定一致，未出现明显整页主题闪变、重复监听或重复动画循环。
5. 全站上述页面及交互状态完成亮色适配；正文对比度满足视觉要求，代码块及控件清晰可读。
6. 两种模式的背景自定义独立生效并保存；旧暗色背景保留，亮色不会被旧默认背景覆盖；恢复默认符合本规格。
7. 星空预览、暂停、减少动态效果、色相、光标和音乐功能通过回归检查；主题切换不重置无关设置。
8. 无效存储或存储不可用时页面仍可使用；静态检查、构建及浏览器行为验证完成，失败与未验证项如实列出。
